# Определитель цветов

Классификатор видов цветов с чат-интерфейсом. Обучение — ResNet-50 в Colab на
GPU, инференс — **ONNX Runtime на CPU, без torch**.

![Интерфейс](docs/screenshot.png)

## Как устроено

```
notebooks/   два ноутбука для Colab: обучение и экспорт в ONNX
model/       веса и описания моделей (приезжают из ноутбуков)
app/         FastAPI: препроцессинг, инференс, API
frontend/    React + Vite: чат
tests/       препроцессинг, контракт API, регрессии по безопасности
```

В зависимостях проекта нет ни torch, ни torchvision: обучение целиком вынесено
в ноутбуки, а рантайму хватает `onnxruntime`. ImageNet-нормализация и softmax
встроены в сам ONNX-граф, поэтому сервер только масштабирует и обрезает
изображение — расхождениям в препроцессинге между обучением и продом неоткуда
взяться. Корректность экспорта проверяется в ноутбуке: выходы torch и
onnxruntime сверяются на одном батче с допуском `1e-4`.

## Результаты

| Модель | Датасет | Классов | top-1 | macro top-1 |
|---|---|---|---|---|
| `flowers102` | Flowers-102 | 102 | 95.3% | — |
| `plantnet100` | Pl@ntNet-300K, срез из 100 видов | 100 | 79.2% | 55.5% |

Разрыв между top-1 и macro top-1 у второй модели — свойство данных: у Pl@ntNet
длинный хвост, и обычная точность вытягивается частыми видами, а среднее по
видам показывает, что происходит с редкими. Flowers-102 сбалансирован, там обе
метрики совпали бы.

## 1. Получить веса

Открыть `notebooks/train_flowers102_colab.ipynb` в Google Colab, включить GPU
(`Runtime` → `Change runtime type` → T4), выполнить `Run all`: ноутбук скачает
датасет, обучит модель в две фазы (сначала классификатор, затем разморозка
верхних блоков), проверит экспорт и предложит скачать два файла. Их нужно
положить в `model/` как есть:

```
model/flowers102.onnx
model/flowers102.labels.json
```

Без них сервер запустится, но честно сообщит в интерфейсе, что модели нет.

Второй ноутбук, `train_plantnet100_colab.ipynb`, обучает модель на сотне видов
из Pl@ntNet-300K — это полевые фотографии вместо студийных снимков.

### Несколько моделей сразу

Сервер находит в `model/` все модели сразу и показывает в шапке выпадающий
список, если их больше одной. Модель — это пара файлов с общим именем:

```
model/
  flowers102.onnx  + flowers102.labels.json
  plantnet100.onnx + plantnet100.labels.json
```

Имена ноутбуки проставляют сами, переименовывать после скачивания не нужно.
Подпись в списке берётся из поля `dataset` внутри описания, по умолчанию
выбирается первая по алфавиту. Пара `model.onnx` + `labels.json` тоже
поддерживается — это раскладка на одну модель, и она становится моделью
по умолчанию, если есть.

Графы загружаются лениво, при первом обращении: каждый ONNX это около 100 МБ
в памяти, и держать их все открытыми незачем.

## 2. Запустить

```bash
uv venv && uv pip install -e .          # зависимости рантайма
cd frontend && npm install && npm run build && cd ..
uvicorn app.main:app --port 8000
```

Открыть http://127.0.0.1:8000 — FastAPI раздаёт собранный фронтенд сам.

### Разработка

Два процесса: бэкенд и Vite с горячей перезагрузкой (он проксирует `/api` на
8000, поэтому CORS не нужен).

```bash
uvicorn app.main:app --reload --port 8000
cd frontend && npm run dev              # http://127.0.0.1:5173
```

## 3. Тесты

```bash
uv pip install --group dev
pytest
```

Тесты собирают игрушечную ONNX-модель с тем же контрактом, что у настоящей,
поэтому проходят и до обучения. Те же тесты гоняются в GitHub Actions на
каждый push.

## API

| Метод | Путь | Ответ |
|---|---|---|
| `GET` | `/api/health` | готовность и число найденных моделей |
| `GET` | `/api/models` | список моделей с архитектурой, числом классов и точностью |
| `POST` | `/api/predict` | `multipart/form-data`: `image` и необязательное `model` → top-3 |

```json
{
  "model": "model",
  "top": [{"label": "sunflower", "probability": 0.981}, ...],
  "uncertain": false,
  "latency_ms": 118.4
}
```

`uncertain` поднимается, когда лучшая вероятность ниже 0.25: модель знает
только цветы и для постороннего снимка всё равно назовёт три вида, поэтому
интерфейс предупреждает об этом явно. Порог невысокий намеренно — label
smoothing при обучении срезает сверхуверенность, и верные ответы часто идут с
вероятностью 0.3–0.5.

## Если выкладывать в сеть

По умолчанию всё рассчитано на локальный запуск: `uvicorn` слушает `127.0.0.1`,
аутентификации нет, ограничения частоты запросов нет. Прежде чем открывать
сервис наружу:

- поставьте обратный прокси и продублируйте в нём лимит на размер тела
  (`client_max_body_size 10m` в nginx) — заголовок `Content-Length` клиент
  может и не прислать;
- добавьте ограничение частоты запросов: один инференс занимает около
  100 мс процессорного времени, и поток запросов легко займёт все ядра;
- подкладывайте в `model/` только свой `model.onnx`. Чужой файл модели — это
  не данные, а исполняемый граф, и доверять ему нужно так же, как коду.

## Датасеты

Веса в репозиторий не кладутся — их надо обучить самостоятельно по ноутбукам.
Сами датасеты распространяются их авторами на собственных условиях:

- [Pl@ntNet-300K](https://zenodo.org/records/4726653) — CC BY-SA 4.0,
  статья на NeurIPS 2021 Datasets & Benchmarks.

Лицензия этого репозитория распространяется на код, но не на данные и не на
обученные на них веса.
